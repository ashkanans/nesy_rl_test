# Spec Suite Notes (Milestone 1: Issue 1.4)

This note defines the current specification preset suite and naming conventions.

## Proposition naming convention

Token propositions follow position-aware symbols generated by the adapter:

- state dimension: `s<idx>_bin<value>` (e.g., `s0_bin22`)
- action dimension: `a<idx>_bin<value>`
- reward/value dimensions: `r_bin<value>`, `v_bin<value>` when present
- explicit end-of-trace symbol: `end`

For Milestone 1 presets, formulas primarily use state predicates.

## Environment presets

## ColourBomb (`specs/cb_specs.py`)

- `avoid_bombs`
  - formula: `G(!(s0_bin22 | s0_bin27 | s0_bin43 | s0_bin78))`
  - purpose: avoid known bomb states.
- `avoid_single_bomb_22`
  - formula: `G(!(s0_bin22))`
  - purpose: minimal single-unsafe-state safety check.

## CLI and precedence policy

- Runtime `--spec` support in Milestone 1: `cb`, `nrm_nav` only.
- `frozenlake` and `antmaze` presets are validated by compilation tests, not runtime training/eval scripts.
- Formula source must be unambiguous:
  - use either `--spec <preset>`
  - or manual `--ltl_formula` / `--ltl_formulas`
  - never both.

## Validation hooks

- Spec registry includes all four environment groups.
- Unit tests compile every preset formula into a DFA.
- Runtime tests exercise `--spec` path for supported environments.
